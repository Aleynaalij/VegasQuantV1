## Reconciliation and bounded gaps

1. The UI's six legacy NFL checks and server health's four-provider list differ. Neither is a
   multisport completeness check. Correct UI scope now; operational expansion needs a separately
   reviewed contract, not an extra cron or widened telemetry in this patch.
2. `sports-sync` writes intermediate ingestion rows and terminal **error** summaries, not a
   uniformly complete success summary. Do not treat the newest ok ingest row as full sport health.
   Adding success/skip telemetry requires a later decision and collector review; not enabled here.
3. NHL/college job pacing can be 3h while quote TTL is 30min. A universal 30min **quote** rule must
   stay, but must not be reused as every job's expected fetch interval. Existing NFL alarms stay
   unchanged; no new multisport expected-age numbers are invented in this patch.
4. A global latest-100 feed-run read can omit a quieter provider under heavy traffic. Missing from
   this sample means not verified, not proven missing in storage. A per-provider bounded read API
   is a design item, not a new endpoint here.
5. A successful research workflow may be throttled, lack qualifying legs or lack credentials.
   Require durable original post/journal readback at release; do not infer publication from green CI.

Release verification must separately establish installed code/migrations, actual cron commands,
consented operational ownership, latest provider evidence and original post/result bindings. None
of these require a collector rerun merely to fill this document.
